# Contracts (v1)

These are the ai_os v1 contracts from [the architecture](../architecture.md). They define payloads, the legal sequence, and the errors for that sequence. They do not start workers, write to total-agent-memory, or render the dashboard.

The package is `@t3tools/ai-os-contracts` (`packages/ai-os-contracts`). Schemas are Effect Schema. Decode with `onExcessProperty: "error"` (`strictParse`) so an undeclared field is rejected. Examples for the first sequence live in `packages/ai-os-contracts/src/examples.ts`. Contract tests live next to the schemas.

`applySequenceEvent` and `applyMemoryEvent` decode the current value and the event, apply the transition, then decode the result. A payload that fails its schema is `invalid_payload`. It is not stored. `buildRetrieval` decodes the graph, the request, and the candidates the same way.

## Sequence

Request, assignment, execution, independent QA, rework, accepted result. Progress, usage, control, and delivery extend that sequence. Shared memory is a separate graph.

| Phase            | Kanban  | Legal events                                                                                                                                                                                          |
| ---------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| idle             |         | intake                                                                                                                                                                                                |
| requested        |         | acknowledge                                                                                                                                                                                           |
| acknowledged     | Ready   | assign                                                                                                                                                                                                |
| assigned         | Ready   | start_execution, cancel, transfer_ownership, open_attempt                                                                                                                                             |
| executing        | Running | submit_completion, lease_expired, report_progress, heartbeat, heartbeat_lapsed, report_usage, record_advisory, deliver_review, record_runtime_models, cancel, fail, operator_fail, transfer_ownership |
| awaiting_qa      | Review  | qa, cancel, record_runtime_models                                                                                                                                                                     |
| qa_incomplete    | Review  | qa, cancel, record_runtime_models                                                                                                                                                                     |
| rework           | Ready   | start_execution, cancel, open_attempt                                                                                                                                                                 |
| rework_capped    | Blocked | resume_rework                                                                                                                                                                                         |
| accepted         | Done    | start_execution, deliver                                                                                                                                                                              |
| review_delivered | Done    |                                                                                                                                                                                                       |
| recovery_pending | Blocked | resolve_recovery                                                                                                                                                                                      |
| failed           |         | retry                                                                                                                                                                                                 |
| cancelled        |         | continue                                                                                                                                                                                              |

`requested` is the durable receipt of the intake. It is not confirmed, and it is not on the board yet. Acknowledge is the confirmation, and it carries the task link. A later `start_execution` from `accepted` drops the previous acceptance, so a new revision has to be submitted and reviewed again. `failed` and `cancelled` are off the board.

`SequenceState` is a discriminated union on `phase`. A phase only decodes with the records that phase requires. `accepted` requires the assignment, the completion, an available accept verdict, and the delivery acks. `awaiting_qa` can carry only an unavailable verdict. `qa_incomplete` keeps the submitted findings and the label `Awaiting a verified reviewer` until a verified reviewer submits. `review_delivered` is an advisory finish. It has no QA verdict. `recovery_pending` requires the label `Execution status unknown`. A payload that is only `{ phase: "accepted" }` does not decode.

An open attempt has a generation and a lease id minted for that generation (`lease-1` for generation 1). A new start, a retry, and an ownership transfer while executing each move to the next generation and lease, and clear the lease expiry and partial progress. Worker events — progress, heartbeat, heartbeat lapse, usage, completion, lease expiry, and `fail` — carry that generation and lease id. A write that names any other pair is `stale_generation` and leaves the run where it is. Stored progress and stored completion have to name that same generation and lease. A state that forges a different pair does not decode. QA also checks that the completion belongs to the current run. `operator_fail` is not a worker event. It is a control command with an actor and an idempotency key.

## Intake

`IntakeV1` is the payload merged in the first contracts batch: workspace, project, request, constraints, acceptance criteria, and authorization (`standing` or `explicit`). `IntakeV2` is that payload plus a required originating conversation id. The sequence accepts either. The id is opaque and case-sensitive. Leading and trailing whitespace is trimmed. Any remaining whitespace, control character, or zero-width character is rejected. `Thread-A` and `thread-a` are different conversations. Model names and git object ids stay case-insensitive.

`IntakeAcknowledgmentV1` is a separate payload. `durable` is the literal `true`. `taskLink` must be exactly `ai-os://tasks/{taskId}`: that scheme, that path, and no extra segment, query, or fragment. A string that only contains the task id is not a link. A `false` durable flag, a missing link, or an acknowledgment before the intake fails. The failure before any intake is `confirmation_before_durable_receipt`.

## Assignment

`AssignmentV1` names the worker, the attempt, the implementer model, and a `ContextPackageSnapshotV1`: requirements, memory versions, repo commit, authorization scope, and created time. The snapshot has no vector field and no candidates field. Decode and assignment both deep-copy that snapshot and freeze the copy, so later mutation of the caller's object does not change the recorded context, and mutation of the stored snapshot throws. The repo commit is a full git object id, 40 or 64 lowercase hex characters.

## Completion submission

`CompletionSubmissionV1` carries the open generation, the open lease id, the claimed outcome, the exact `artifactRevision`, and at least one evidence item (`diff`, `commit`, `test`, `browser`, `preview`, `deployment`, or `readback`). An artifact revision is a git object id, a Drive file id plus version, or a named page, preview, deployment, or document id. A git object id is exactly 40 hex characters (SHA-1) or 64 (SHA-256), stored lowercase. Abbreviated ids are rejected. Drive file ids stay case-sensitive. Submitting a completion moves `executing` to `awaiting_qa` only after the implementer's actual model is recorded. An unknown actual is `qa_model_unknown` and the card stays `executing`. It does not accept the work. Repeating the revision that QA sent back for rework, including the same full git id in a different case, is `revision_mismatch`. A completion has a claimed outcome. It does not carry an idempotency key.

## QA verdict and rework

`QaVerdictV1` is one of:

| Variant                     | Result                                                                                                                                                                                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `availability: unavailable` | Stays `awaiting_qa`. No verdict and no acceptance.                                                                                                                                                                                                                                                                                   |
| `verdict: rework`           | Counts one round on the task when both actuals are known, different, and match the run records. Moves to `rework`, or to `rework_capped` once three rounds are on the task. Findings are required. A capping verdict needs `recommendation`. An unknown actual stays `qa_incomplete` with those findings and does not count a round. |
| `verdict: accept`           | Moves to `accepted` on that same check. `acceptedRevision` must equal `artifactRevision`, and that revision must be the one in the completion submission. An unknown actual stays `qa_incomplete`.                                                                                                                                   |

Each applied rework verdict appends one round to the task's rework ledger: the completion's claimed outcome, the commit SHA when the revision is git, and the findings. The ledger is not on the attempt or the run. A new attempt id (`open_attempt`), a new generation, a handoff, a retry, recovery, a reload, and an incomplete review all keep it. No event clears it. After three rounds the task is Blocked, labeled `Needs Jim: rework cap reached`. The notice carries the latest findings, every round, and the agent's recommendation. `start_execution` and a board launch are refused. `resume_rework` is the only way out, and only when `actorId` is `jim`. It records his decision and returns the task to `rework` without clearing the count, so the next rework stops again.

A formal verdict, rework or accept, compares the implementer's actual base model with the reviewer's actual base model. Both come from runtime metadata, not from the assignment, not from a usage measurement, and not from the names on the verdict. The qa event names the submitting session's thread or run. The server records the reviewer from that session's provider metadata, then checks the verdict against the run records. The thread has to belong to this task, and it cannot be the implementer's own thread. If either actual is unknown, the verdict is not applied. The phase becomes `qa_incomplete`, the findings stay attached, and the card waits for a verified reviewer. A later verified session can replace that unknown reviewer. The earlier findings stay on the run as `priorReviews` and do not count as independent QA. A verified reviewer already recorded is not replaced. Nothing is substituted. A model is `{ provider?, model }`. Provider is attribution (`openai/gpt-5.4` and `azure/gpt-5.4` are the same model, and so is a bare `gpt-5.4`). The schema check compares the two model names on the verdict. The transition compares the runtime actuals. It rejects the same base (`qa_same_model`) and a payload that names a different model than the runtime (`implementer_mismatch`) for both verdicts. Acceptance compares canonical revisions, so a full git id matches regardless of case. An unavailable verdict cannot also carry an acceptance. There is no event that skips QA. Advisory findings can flag defects and recommend changes. They are not independent QA.

The comparison runs for both verdicts. A stored `rework` or `accepted` card is checked again when both `implementerRuntime` and `reviewerRuntime` are present. A card saved before those fields existed still decodes. A stored accepted card whose runtime actuals share a base does not.

## Progress

`ProgressReportV1` is a snapshot for the open generation and lease: `working` or `blocked`, blockers, and partial artifacts. A blocked report needs at least one blocker. A blocker names the summary, the owner, and a concrete next action. A working report cannot carry blockers. Partial artifacts use the same revision types as completion, so an abbreviated git id is rejected. The stored report is frozen.

`HeartbeatV1` names the generation, the lease id, and when that lease expires. Instants are RFC3339 UTC with a `Z` suffix. The month, day (including leap years), hour, minute, and second are range-checked, and the parsed value must format back to the same string. A leap second (`60`) and `24:00` are rejected. Decode keeps the submitted text, so `.1Z` is not rewritten to `.100Z`. Ordering still compares the instants: `.1Z` and `.100Z` are the same millisecond, and `.001Z` is after a whole second. A heartbeat refreshes `leaseExpiresAt` only when both the generation and the stored lease id match. It does not replace the lease id. `heartbeat_lapsed` and `lease_expired` for that same pair move `executing` to `recovery_pending`. A stale pair is rejected and leaves the run executing. Neither event returns the attempt to Ready.

## Shared memory

Node kinds and relationship types are the ones in [the memory schema](../memory-schema.md). `MemoryGraphV1` stores facts and relationships. A fact is `proposed`, `accepted`, or `superseded`. A relationship is `proposed` or `accepted`. Both carry provenance (who, when) and a validity window. Proposed is not knowledge. `accept_fact` is the explicit acceptance. `supersede` records an accepted `SUPERSEDES` relationship from the newer accepted fact to the older accepted fact and marks the older fact `superseded`. A fact cannot supersede itself. The older fact stays in the graph. `historyFacts` returns accepted and superseded facts. `packageFacts` returns accepted facts in that project whose window covers `asOf` and that are not the target of an accepted `SUPERSEDES` edge valid at `asOf`. A superseded fact is never current. Graph decode checks that status against the edges. Fact ids are unique, and relationship ids are unique. An accepted `SUPERSEDES` edge starts at a fact that was accepted. That source may later be superseded by the next fact in the chain. It cannot be proposed. The edge ends at the superseded fact. A proposed fact cannot be the target of that edge. A superseded fact without a matching accepted edge, an accepted edge whose target is not superseded by that newer fact, a self-edge, a cross-project `SUPERSEDES` edge, or a cycle of accepted `SUPERSEDES` edges is `invalid_graph`. That graph is rejected. It is not packaged as an empty current set. A proposed edge does not supersede. There is no shared-scope exception in v1. Windows are compared as instants.

`buildRetrieval` builds that package from the graph first, then attaches `candidates` beside it. Candidates cannot add, remove, or reorder package entries. The package schema itself has no candidates field. This contract does not write total-agent-memory.

`SubmissionV1` is how an agent submits facts and relationships. It names the submission, an idempotency key, the project, the author, the task and attempt, source evidence, and the accepted fact versions the author read. `applySubmission` returns one outcome: `accepted`, `duplicate`, `conflict`, `rejected`, or `pending`. A proposal stays proposed. An agent cannot accept. The accepting authority can accept a new version only when the expected revision is still current; that writes a new accepted fact and a `SUPERSEDES` edge, and the older fact stays in the graph. A contradictory or stale submission keeps the accepted fact and records an open conflict attributed to the submitting agent. The accepting authority resolves that conflict with another `SubmissionV1`: accepting the proposed text or a corrected text supersedes the old fact, and accepting the current text again leaves that fact in place. Either way the conflict records the resolving submission. The same idempotency key returns `duplicate` and does not write again. A rejected submission writes nothing. Facts and relationships in one submission publish together. The author's id is the fact's provenance, which is what the memory view attributes to an agent.

`prepareTaskMemory` builds the package a run receives before coding: current instructions, decisions, and knowledge, plus open conflicts. Artifact and log bodies stay in the package detail; the orientation carries their summary. There is no token cap. The read receipt names the attempt, the agent, the digest, and the fact versions that were supplied. It records that the context was supplied. A running attempt submits one write for its own attempt and project: a recorded fact, or a findings proposal. The launch prompt includes how to submit it. A recorded fact with no current statement is accepted by the authority, so the next run's read receipt includes it. A findings proposal stays proposed. A contradictory or stale proposal keeps the accepted fact and records an open conflict for the Memory Steward. An explicit statement that nothing durable changed is written only when the attempt finishes without a write, and it does not replace a write already made. The write receipt is the submission receipt.

## Usage

`UsageMeasurementV1` is one of `reported_tokens`, `estimated_cost` (USD minor units), `subscription_allocation` (basis points), or `unknown`. Each measurement carries attribution: project, task, attempt, agent, platform, provider, and model. A payload that mixes those kinds is rejected. `UsageLedgerV1` is the list of measurements. It has no total field. `usageTotals` adds values only inside a kind. Unknown increments a count. It does not become tokens or cost. `report_usage` appends one measurement to the open run and carries the open generation and lease id. The project, task, and attempt have to match the intake and the assignment. Cancel, continue, retry, and an executing ownership transfer keep the measurements with the attempt.

## Control and recovery

Control commands carry an idempotency key. That key is not a completion claim. The key is bound to a canonical fingerprint of the whole command payload. The same key and the same payload replay the current state. The same key and any other payload, including a different owner or blocker, is `idempotency_conflict`.

| Command              | From                                                    | Result                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cancel`             | assigned, executing, awaiting_qa, qa_incomplete, rework | `cancelled`. Off the board.                                                                                                                                                        |
| `continue`           | cancelled                                               | `assigned` (Ready). This is the only way back from cancelled.                                                                                                                      |
| `operator_fail`      | executing                                               | `failed`, with an actor and a blocker. Off the board. Not fenced by the lease.                                                                                                     |
| `retry`              | failed                                                  | `executing` at the next generation, until `retryCount` reaches `retryLimit` (3).                                                                                                   |
| `transfer_ownership` | assigned, executing                                     | The worker changes. An executing transfer also advances the generation.                                                                                                            |
| `resolve_recovery`   | recovery_pending                                        | `continue` returns to Ready, `cancel` leaves the board, `fail` records the blocker. An advisory continue supplies `nextAttemptId`. A non-advisory continue keeps the open attempt. |
| `open_attempt`       | assigned, rework                                        | Replaces the attempt id. The rework ledger stays.                                                                                                                                  |
| `resume_rework`      | rework_capped                                           | Jim only. Records his decision and returns to `rework`. The count stays.                                                                                                           |

`recovery_pending` accepts no other event. An expired lease, a lapsed heartbeat, or a lost advisory process does not become Ready on its own. Advisory work still uses a process and a worktree, so a retry waits until that process is confirmed stopped, removes the worktree, and starts a new attempt. A late result from the old attempt is `attempt_mismatch`. A retry past the limit is `retry_limit_reached` and stays `failed`.

## Result delivery

`deliver` is legal only from `accepted`, and only for the exact accepted revision. The destination is the explicit `dashboard` target. `conversation` is legal only for an `IntakeV2` task, and only when the conversation id is exactly that intake's originating conversation. A v1 intake has no originating conversation, so conversation delivery is `delivery_origin_mismatch` and the dashboard is the only target. Any other conversation id is the same error. The state stores one ack per destination. The same idempotency key replays that ack only when the delivery fingerprint matches. A different payload for that key is `idempotency_conflict`. A second key for a destination that already has an ack does not add another. A different revision is `delivery_revision_mismatch`.

## Errors

Invalid payloads fail schema decode. A failed transition is `ContractTransitionError`. An unknown actual model is the exception: the verdict is not applied, and the card becomes `qa_incomplete` with its findings kept.

| Reason                                | When                                                                                                                                                                                                       |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `confirmation_before_durable_receipt` | Acknowledge before the intake is recorded.                                                                                                                                                                 |
| `illegal_transition`                  | The event is not legal for the phase.                                                                                                                                                                      |
| `task_mismatch`                       | The payload task or usage project is not the acknowledged work.                                                                                                                                            |
| `attempt_mismatch`                    | The payload attempt is not the open assignment.                                                                                                                                                            |
| `implementer_mismatch`                | QA names a different implementer or reviewer than the runtime.                                                                                                                                             |
| `qa_same_model`                       | The reviewer's actual base model is the implementer's actual base model.                                                                                                                                   |
| `qa_model_unknown`                    | Completion was submitted before the implementer's actual model was recorded, or a verdict was asked with an actual missing. Completion stays put. A verdict becomes `qa_incomplete` and the findings stay. |
| `revision_mismatch`                   | Rework submits the same artifact revision again.                                                                                                                                                           |
| `acceptance_revision_mismatch`        | QA or acceptance names a revision other than the submitted one, or the revision already sent back for rework.                                                                                              |
| `recovery_pending_not_ready`          | Any event other than `resolve_recovery` while recovery is pending.                                                                                                                                         |
| `invalid_payload`                     | The state, event, or result does not match its schema.                                                                                                                                                     |
| `stale_generation`                    | A worker event names a generation or lease other than the open run.                                                                                                                                        |
| `retry_limit_reached`                 | Retry was asked at the retry limit.                                                                                                                                                                        |
| `rework_cap_reached`                  | Any event other than Jim's `resume_rework` while the rework cap holds, including an agent resume.                                                                                                          |
| `rework_cap_needs_recommendation`     | A rework verdict that would reach the cap has no recommendation.                                                                                                                                           |
| `idempotency_conflict`                | The idempotency key was already used for a different payload.                                                                                                                                              |
| `delivery_revision_mismatch`          | Delivery names a revision other than the accepted one.                                                                                                                                                     |
| `delivery_origin_mismatch`            | A conversation delivery does not name the intake's originating conversation.                                                                                                                               |
| `memory_not_eligible`                 | The event is not acceptance of a proposed fact, or not a same-project supersession of two distinct accepted facts.                                                                                         |
| `invalid_graph`                       | SUPERSEDES edges disagree with fact status, leave their project, point at themselves, or form a cycle.                                                                                                     |

## Tests

From the repo root, after install:

```sh
vp run --filter @t3tools/ai-os-contracts test
vp run --filter @t3tools/ai-os-contracts typecheck
```

The tests cover valid and invalid payloads, the happy path, illegal transitions, canonical model and revision checks, the exact task URI, frozen snapshots, phase invariants, generation fences on every worker event, usage kinds, memory acceptance and supersession, candidate exclusion, bounded retry, explicit recovery, idempotency, and delivery acks.
